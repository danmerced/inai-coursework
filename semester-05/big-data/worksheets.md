# Big Data — теоретические практики

## Неделя 1. Роли технологий

Рассмотрим заказ поездки. Клиентское приложение отправляет запрос; транзакционная БД хранит заказ, водителя и состояние оплаты. Лог событий принимает сообщения о действиях, файловое хранилище сохраняет архив, вычислительный движок обрабатывает историю. BI показывает агрегаты. Каталог метаданных описывает структуру и происхождение данных; ML-инструмент обучает модель.

Commit означает, что связанные изменения заказа и оплаты фиксируются вместе; при сбое rollback отменяет незавершённую транзакцию. Лог для аналитики не заменяет транзакционную БД.

## Неделя 3. Выбор технологии

| Сценарий | Минимальная технология | Причина |
|---|---|---|
| Маленький CSV поездок | Python / SQLite | Умещается в памяти, не нужен кластер |
| Два года кликов | Объектное хранилище + Parquet + пакетный SQL | Разделение по датам уменьшает чтение |
| Авторизация карт с низкой задержкой | Транзакционная БД / быстрый key-value кэш с контролем согласованности | Короткий запрос, атомарное изменение лимита |

CAP — при сетевом разделении приходится выбирать между доступностью и согласованностью. ACID подходит для атомарных платежей; BASE — для сценариев, допускающих eventual consistency, например агрегатов просмотров.

## Неделя 10. Batch и streaming

Batch считает итоги за завершённый интервал; streaming обновляет показатели по продолжающемуся потоку. Время события отличается от времени поступления. Допустим, событие 12:05 пришло в 12:20: при watermark 10 минут и максимуме времени события 12:20 оно считается опоздавшим. Политика: вести журнал поздних событий, корректировать дневной batch, дедуплицировать по event_id. Не обещать exactly-once без проверки семантики источника, sink и checkpoint.

## Неделя 11. Hadoop и Spark

HDFS делит файлы на блоки, хранит реплики и метаданные. MapReduce выполняет map → shuffle → reduce, Hive обеспечивает SQL над хранилищем, Spark строит DAG и выполняет операции параллельно. Каталог хранит таблицы, схемы и партиции. Для 6 событий локальный SQL дешевле; кластер имеет смысл при объёме, который не помещается на одном компьютере, или долгих параллелизуемых расчётах.

## Неделя 12. Интегрированная лабораторная

Проверка качества: 6 строк = 4 принятые + 2 карантинные, reasons missing_city и unknown_kind по одной. Нормализованные строки — подмножество accepted, не прибавляются к итогу. JOIN anti оставляет поездку 6 с driver_id 4, которого нет в справочнике. Spark-скрипт печатает физический план; Exchange означает shuffle данных между партициями для группировки. Фактический план и Parquet read-back нужно получить после установки Spark.

## Неделя 15. Кластеризация

KMeans минимизирует сумму квадратов евклидовых расстояний. Масштабирование предотвращает доминирование признака с большим разбросом; часы 23 и 0 соседние на круге, но далеко по линейной шкале. В отдельном эксперименте можно представить час sin/cos, однако здесь только pages и hour как в условии. Синтетические данные имеют три заданные области концентрации, поэтому k=3 естественен. ARI сравнивает две разметки без зависимости от номеров кластеров. При k=8 появляются более мелкие сегменты; устойчивость и размеры оцениваются отдельно, см. результаты. Converted не используется при fit, только при описании. Нельзя считать предсказание cluster label из исходных признаков независимой валидацией и нельзя автоматически отказывать посетителю в обслуживании по кластеру.
