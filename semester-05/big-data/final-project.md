# Интегрированный учебный проект: аналитика поездок и посещений

## 1. Data gate
Все данные синтетические, генерируются локально. Владелец учебного набора — разработчик примера. Колонки ограничены ролью анализа: ID, город, тип события, дата, стоимость поездки; для ML — расстояние, час, дождь, целевые метки. Реальные имена, платежные реквизиты и координаты не нужны. Сырые файлы хранятся отдельно, карантин содержит причину отклонения; при удалении примера удаляется output и генерируемые CSV.

## 2. Curated question
Сколько валидных кликов по городам? Цель: Tashkent 2, Samarkand 1, Bukhara 1. PostgreSQL — week05/06, Spark — week12, локальная проверка — local_analysis.py. Сравниваются одинаковые схемы и фильтры. Приёмка: исходное количество = accepted + quarantine, результаты SQL и DataFrame равны, read-back не меняет результат.

## 3. Supervised learning
Прогноз отмены по известным до начала поездки признакам. По хронологии train 360, validation 120, test 120. Baseline: всегда не отменена, стоимость FP=1, FN=4. Logistic regression; порог только по validation, итог test один раз. Регрессия времени поездки сравнивается со средним train. Синтетика не отражает реальные риски или качество сервиса.

## 4. Clustering
900 посещений, pages/hour, стандартизация, k=3 и 8, seeds 7/8. ARI, размеры и средние исходных признаков; converted после fit. Сравнение представлено в results.md. Решения о персональном доступе нельзя принимать по этим кластерам.

Это интеграция известных компонентов курса. Полный критерий финального проекта пока не получен; фактический запуск Spark/PostgreSQL требуется отдельно.
