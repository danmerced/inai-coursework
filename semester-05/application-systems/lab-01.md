# Лабораторная работа 1 Разработка описания и анализ информационной системы

## Цель
Описать систему, проанализировать осуществимость разработки, распределить роли и составить первоначальный план.

## Введение
В качестве предметной области рассматривается Student Portal — единое информационное пространство института. Здесь проектируется ограниченная часть системы: расписание, учебный профиль, публикация объявлений и администрирование доступа. Это модель для проектирования; не описание всех функций внедрённой системы. Цель — уменьшить число повторяющихся запросов студентов к администрации и хранить актуальную информацию централизованно.

## Описание ИС

| Пользователь | Возможности |
|---|---|
| Студент | Авторизация, просмотр своего расписания и объявлений |
| Сотрудник | Подготовка и обновление расписания и материалов в пределах полномочий |
| Администратор | Управление ролями, группами, публикациями и аудитом |

Основные данные: учётные записи, группы, предметы, учебные занятия, аудитории, объявления, журнал действий. У пользователя одна или несколько назначенных ролей. Расписание связано с группой, временем, аудиторией и дисциплиной. Изменения в расписании публикуются как актуальная версия.

## Анализ осуществимости

Без системы сведения будут распределены между чатами и таблицами: изменения могут потеряться, появятся дублирующиеся сообщения и разные версии расписания. Единая база уменьшает число ручных операций и позволяет проверять согласованность. Доступ студента должен ограничиваться разрешёнными ресурсами; административные операции требуют проверок на сервере.

Технически возможно реализовать web-приложение на Java/Spring Boot, PostgreSQL и Next.js. Для запуска требуются сервер или контейнерная среда, браузеры клиентов, резервное копирование. Использование централизованного API и миграций — решение для проектируемой системы; неизвестно, используются ли эти технологии во всех подразделениях института. На первом этапе импорт учебных данных выполняется на копии или синтетических записях. Реальная интеграция возможна после разрешения владельца данных.

## План проекта

**Ограничения:** учебный MVP, 6 недель, три инженерные роли. Оценки плановые, не фактический бюджет института.

| Этап | Срок | Результат |
|---|---|---|
| Анализ | 1 неделя | Требования, роли, данные |
| Проектирование | 1 неделя | ER/UML, API, UI |
| Реализация | 2 недели | Авторизация, расписание, объявления |
| Проверка | 1 неделя | Приёмочные сценарии, исправления |
| Развёртывание | 1 неделя | Инструкция, резервирование |

| Роль | Ответственность |
|---|---|
| Руководитель-разработчик | План, архитектура, интеграция |
| Аналитик-разработчик | Требования, модели данных, прототип интерфейса |
| Тестер-разработчик | Сценарии, воспроизведение дефектов, проверка доступа |

Оценка трудозатрат: 3 человека × 10 часов в неделю × 6 недель = 180 человеко-часов. При условной ставке 400 сом/час трудозатраты оцениваются в 72 000 сом. Инфраструктура 3 000 сом, резерв 15% от 75 000 — 11 250 сом. Плановый общий бюджет 86 250 сом. Это расчёт учебного сценария, не утверждённая смета.

## Риски

| Риск | Мера |
|---|---|
| Неполные исходные данные | Валидация импорта, пилотная группа |
| Несогласованные изменения занятий | Транзакции, проверка пересечений |
| Избыточный доступ | RBAC, аудит, проверка на сервере |
| Потеря базы | Ежедневные копии, тест восстановления |
| Невыполнение сроков | Приоритет MVP, демонстрация по этапам |

Программные средства: Java 21, Spring Boot, PostgreSQL, Next.js, Git, Docker; рабочие машины разработчиков и тестовый сервер. Проектирование и отчёт выполняются без реальных персональных данных.

## Вывод
Проект осуществим как ограниченный пилот с согласованием источников данных, планом резервирования и назначенными ролями. Перед эксплуатацией необходимы тесты доступа, импорт и приёмка представителем института.
