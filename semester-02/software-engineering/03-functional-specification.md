# Функциональная спецификация

| Экран | Действия | Состояния и ошибки |
|---|---|---|
| Вход | Логин, пароль, кнопка «Войти» | Пустые поля, неверный пароль, недоступная БД |
| Расписание студента | Выбрать дату, перейти на предыдущий/следующий день, выйти | Загрузка, список по времени, «Занятий нет» |
| Расписание редактора | Выбрать группу и день, добавить, редактировать, удалить | Список, пустой список, ошибка загрузки |
| Форма занятия | Выбрать группу и предмет, дата, начало/конец, аудитория, сохранение/отмена | Не заполнено поле, начало после окончания, пересечение времени |
| Подтверждение удаления | Подтвердить или отменить | Успех, ошибка сохранения |

## Сценарий A — просмотр расписания

1. Пользователь вводит данные входа.
2. AuthService проверяет аккаунт, получает роль и группу.
3. ScheduleService получает записи по группе и выбранной дате.
4. Интерфейс показывает занятия в порядке начала. При смене даты запрос повторяется.
5. При выходе состояние сессии очищается.

## Сценарий B — создание занятия

Предусловие: роль редактора, группы и предметы уже заведены.

1. Редактор открывает форму и заполняет поля.
2. Сервис проверяет обязательные поля и startTime < endTime.
3. Репозиторий проверяет пересечение другой записи той же группы или аудитории на эту дату: old.start < new.end и new.start < old.end.
4. При конфликте система объясняет ошибку и сохраняет введённые значения в форме.
5. При успехе запись сохраняется, список обновляется.

## Правила доступа

Просмотр собственной группы разрешён студенту. Редактор видит выбранную группу и может изменять записи. Сервис проверяет роль при каждом изменении. Система запрещает дублирующийся логин, отсутствующие ссылки на группу/предмет и неверный интервал времени.
